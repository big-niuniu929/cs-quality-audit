1系统概览与流程

本系统用于把电商平台客服的原始聊天记录变成可量化、可复核、可跟进的质检结果。导入一对文件后，系统会自动完成：解析会话、匹配标签、判定售前/售后、判断有效性、划分 A/B/C 商机等级、识别电销线索、按维度打分，并把需要人判断的会话放进人工复核队列。

它能帮你做什么

能力说明
自动质检打分满分 100 分倒扣，覆盖响应速度、售前必问、问题解决、留资 4 个维度，60 分为合格线。
商机与线索自动标出 A/B/C 级商机与「电销线索」（客户留了电话/微信等），运营可直接跟进。
可疑会话复核规则拿不准的会话自动进入待复核队列，人工看聊天记录后确认或改判、改分。
AI 辅助可对可疑会话逐条做智能判定（合格/不合格/待复核），并引用原文作为依据；也可对整个筛选结果做智能总结。
汇总与导出按店铺/客服/产品/时间/阶段/商机/有效性筛选，统计与图表联动，结果导出 Excel。

2快速开始

  1. 启动系统双击项目文件夹里的 start.bat。程序会自动寻找运行环境并打开主窗口，首次启动可能需要几秒。
  2. 导入数据在「数据导入」页分别选择聊天记录 .log和会话记录 .xlsx，确认「店铺标记」，点 开始质检导入。等待提示「导入完成：X 会话（匹配标签 X，未匹配独立保留 X）」，系统会自动跳到质检总览。
  3. 看结果总览页看指标、图表与会话列表；双击任意行打开会话详情，查看聊天记录与扣分明细。
  4. 复核与跟进「人工复核」处理可疑会话；「电销跟进」按电话号码逐个联系客户；最后「导出 Excel」交给主管或存档。
小提示：右上角的月亮/太阳按钮可切换深色 / 浅色主题，默认浅色；您的选择会被记住。表格中内容显示不全时，把鼠标停在单元格上即可看到完整内容。

3数据导入

3.1 文件要求

文件格式要求说明
聊天记录.log 或 .txt电商平台客服导出的原始聊天记录，包含「会话开始/结束」标记、账号与时间行、消息正文。
会话记录.xlsx工作表名为「咨询会话查询」，用于补充型号、商品、满意度、是否解决等标签。
注意：两个文件应当是同一时期导出的一对（会话数与时间范围吻合），否则会出现大量「未匹配」。匹配不上的会话不会丢，仍会独立保留并参与质检，只是缺少 Excel 标签。

3.2 店铺标记

会话记录里不包含店铺信息，因此导入时需要手动选择本次数据所属的店铺。下拉框支持直接输入新店铺名称；点 管理店铺 可增删店铺（保存在本地配置中），已导入过的店铺会自动合并进来。

3.3 去重与批次

  • 自动去重：系统按聊天记录文件的内容指纹判断，同一份 .log 重复导入会提示「已于 X 导入过（批次 X），未重复导入」，不会产生重复数据。
  • 批次历史：页面下方列出批次号、店铺、导入时间、数据范围、会话数、匹配数，方便追溯每次导入。
  • 删除批次：选中批次行后点 删除选中批次，会连同该批次的会话、质检结果、AI 缓存一起删除，并写入审计日志，不可撤销，请谨慎操作。

3.4 常见导入问题

提示 / 现象处理办法
「请同时选择 .log 和 .xlsx」两个文件必须都选，缺一不可。
「该聊天记录已于 X 导入过」正常的去重提示，无需处理；如需重算，先删除对应批次再导入。
「导入失败：找不到文件…」文件被移动或删除，重新选择路径即可。
「导入失败：文件被占用或无读取权限」Excel 正被打开占用，关闭文件后重试。
「导入失败：数据格式不正确」确认选择的是同一时期导出的原始文件，且表格结构未被改动。

导入失败时完整的技术堆栈会打印在启动窗口的终端里，遇到无法处理的情况可截图给技术支持。

4质检总览

4.1 指标卡

指标含义
总会话当前筛选范围内的会话总数。
售前 / 售后按规则分流后的会话数；售后只统计数量与有效性，不参与评分。
有效判定为有效咨询的会话数（不含无效与待复核）。
A 级 / B 级 / C 级售前商机等级数量，A 级最高。
电销线索留下电话/微信等联系方式的会话数，可直接跟进。
售前平均分售前会话的平均分；已复核的按人工最终分计算，未复核的按规则计算分。

4.2 筛选

顶部筛选条支持：店铺、客服、产品、阶段（售前/售后/待复核）、商机（A/B/C/无）、有效（有效/无效/待复核）、开始与结束日期。任意条件变化后，指标卡、两张图表、下方表格会一起刷新。筛选条件可组合使用，例如「店铺=某店 + 客服=某人 + 日期=本周」。

4.3 图表

  • 商机等级分布：A / B / C 级会话数量对比。
  • 售前评分分布：90–100、80–89、70–79、60–69、60 以下五档。

4.4 会话表格

共 11 列：时间、店铺、客服、产品、阶段、有效、商机、分数、智能判定、电话、跟进建议。双击任意一行打开会话详情。表格内容过长时悬停可看完整内容；「智能判定」列中，蓝色表示 AI 已给出结果（如「智能：合格」），灰色「规则」表示仅使用了规则初筛结果。

4.5 三个操作按钮

按钮作用
智能批量质检可疑会话对当前筛选范围内、尚未复核且被标记为可疑的会话逐条调用 AI，判定「合格 / 不合格 / 待复核」并给出理由与原文依据。弹出的进度条会实时显示进度，可取消。相同内容命中缓存时不重复调用。
智能总结当前筛选把当前筛选结果交给 AI 生成中文总结（整体服务质量、共性问题、商机情况、改进建议），适合周会汇报。
导出 Excel把当前筛选结果导出为 .xlsx，包含 16 列：时间、店铺、客服、客户、产品编号、产品名称、阶段、有效、商机、电销线索、计算分、最终状态、复核状态、复核说明、扣分明细、跟进建议。

5会话详情

双击总览、人工复核或电销跟进列表中的任意一行，都会打开「会话详情」弹窗。从上到下依次是：

5.1 信息条

客服、客户、店铺、时间、型号；阶段、有效性、商机等级、是否电销、计算分、最终分、复核状态、致命候选数量；扣分明细；智能判定结论。

5.2 判定原因与智能依据

「判定原因」用中文列出命中的规则（如「客户有明确需求」「客户留下联系方式」）；若 AI 参与过判定，会显示「智能判定依据」，按「第 N 条」引用聊天原文，方便核对。

5.3 聊天记录（微信风格）

  • 客服在右侧、绿色气泡；客户在左侧、白色气泡；机器人与模板消息居中显示为灰色系统提示。
  • 时间按微信规则分组：当天每 5 分钟显示一次；超过 1 天、小于 1 周显示「星期几 时间」；超过 1 周显示日期。换天时出现「今天 / 昨天 / 月日 星期X」的分隔条。
  • 点击任意时间标签，可在简洁时间与完整时间（如「2026年9月2日 星期三 15:30」）之间切换，再点一次切回。
  • 图片和商品链接会自动整理为「［图片］」或可读文本，不会出现大段乱码。

5.4 人工最终分与复核

底部「人工最终分」可直接输入 0–100 的分数，点下方任一结论按钮保存：

按钮行为
确认合格按当前分数保存，复核状态变为「已完成」，结论为合格。
改判不合格按当前分数保存，结论为不合格。
确认致命项(59分)确认命中致命项，分数固定为 59 分并判不合格。
关键：修改分数后必须点其中一个结论按钮才会保存；保存后总览的分数会立即更新，同时写入审计日志。即使会话不在待复核队列里，也可以双击进入详情手动改分。

6人工复核

6.1 哪些会话会进入待复核

  • 阶段或有效性被规则判为待复核（规则拿不准）；
  • 售前有效，但三组必问信息（会议室规模/人数、视频会议需求、使用场景）一个都没覆盖；
  • 会话尚为「待复核」状态（未完成人工结论）。

已提交人工结论的会话会自动移出队列。队列条数会显示在页面右上角。

6.2 操作流程

  1. 刷新队列点 刷新队列 获取最新待复核会话。
  2. 查看详情双击某一行打开会话详情，重点看「判定原因」「聊天记录」「扣分明细」。
  3. 给出结论修改「人工最终分」，填写「复核说明（改判理由）」，点「确认合格」或「改判不合格」；命中致命项则点「确认致命项(59分)」。
  4. 确认生效该行从队列消失，总览分数与状态同步更新，审计日志记录操作人、时间与前后值。
复核口径建议：优先处理 A 级商机、电销线索和「客服未答复」的会话；改判时把理由写清楚（如「客户只是询价，无购买信号」），方便日后追溯。

7电销跟进

只要会话中出现电话号码，或客户主动留下微信/联系方式等关键词，系统就会把该会话标为「电销线索」，并自动进入本页面。该会话同时会被判为有效 + A 级商机。

7.1 电话号码识别规则

系统能识别以下格式，并照原样展示（平台脱敏的星号会保留）：

格式示例说明
13800000000完整 11 位手机号。
159*******5平台脱敏号码（中间用 * 遮挡），照原样展示，可直接用于回访核对。
159******45、159****1234尾部保留多位数字的脱敏格式，同样能识别。
159 1234 5678、159-1234-5678带空格或短横线的号码，会自动去除分隔符后识别。

识别条件：以 1 开头、第二位 3–9、共 11 位且最后一位是数字；中间允许 * x X 或全角＊×等屏蔽符。号码被拆成多行、或只出现在图片里时无法识别。

7.2 页面字段

时间、店铺、客服、客户、产品、电话号码、跟进建议。没有识别到号码但命中联系方式关键词的会话，「电话号码」列显示「—」。

8智能设置

8.1 配置项

字段说明
接口地址公司 AI 网关地址，例如 https://gateway.example.com/v1
模型名称使用的模型（由接口提供方分配）。
协议类型对话接口（chat_completions，常见）或 响应接口（responses，公司新协议）。
接口密钥以密码框显示；只保存在本地配置文件，不写入代码、不随导出文件外传。

8.2 操作

  1. 填写配置按主管提供的地址、模型与密钥填写。
  2. 测试连接点 测试连接，显示「连接成功（模型 X，协议 对话接口）」即配置正确；失败会提示中文原因（如无法连接服务器、超时、密钥错误）。
  3. 保存配置点 保存配置，配置立即生效，后续批量质检与智能总结都会使用它。
AI 与规则的关系：规则负责确定性的初筛与打分，AI 只做辅助判断与总结，不会改变规则算出的分数；AI 结论同样以「智能：」前缀展示，最终结论仍以人工复核为准。

9规则逻辑框架

下面这套逻辑决定了每条会话「是什么、值多少分、要不要人看」。理解它，才能解释为什么某条会话被判成 A 级或扣了 20 分。

9.1 总原则

  • 先分流，再判定：先分清售前/售后，商机分级只针对售前。
  • 有效性是门槛：售前会话先判有效/无效，有效才进入 A/B/C 分级。
  • 商机与评分是两条线：A/B/C 是商机等级，不是分数；评分单独按 100 分倒扣计算，两者分别展示。
  • 命中多个取最高：A > B > C；但所有命中的原因都会记录，便于复核解释。
  • 拿不准就交给人：不确定的会话标为「待复核」，进入人工复核队列，不强行下结论。

9.2 第一步：售前 / 售后分流

情况判定说明
出现售后关键词（安装、维修、退货、换货、订单、发票、物流、配送、售后、保修、坏了、故障、退款等）且无售前信号售后只统计数量与有效性，不参与 A/B/C 与评分。
出现商机信号（询价、优惠、要买、对比、计划购买等）售前继续判有效性与商机等级。
售后与售前信号同时出现按售前处理优先按售前跟进，保留售后信号。
客户有消息但既无售后也无商机信号售前（待确认）默认按售前咨询处理，逐步确认。
完全没有客户消息待复核交人工确认。

9.3 第二步：有效性判定

阶段情况判定说明
售前没有实质性咨询内容，也没有明确业务信号无效客户点进来没问实质问题。
短会话（≤ 5 条消息）且无询价/购买/对比/优惠/联系方式信号无效客服时间成本被浪费。
客户有明确需求但没等到客服回复就离开待复核需要人工确认是否算有效。
其余情况（有实质需求且客服已响应）有效进入 A/B/C 分级与评分。
售后客服完全没回复待复核客户未等到答复。
只有一条售后问题，客服简短答复且无后续跟进无效视为未真正解决。
客服给出解决/转交表述（建议、可以、支持、步骤、联系、转交、热线等）或答复较完整有效售后问题已解决或转交。

9.4 第三步：商机 A/B/C（仅售前且有效）

等级命中任一即成立跟进动作
A 级① 留下联系方式（电话/微信/手机号）；② 明确表达购买我方产品（就买、下单、买一台、要了、确定买、多少钱能拿下）；③ 主动询问优惠/折扣/活动；④ 明确需求且有购买时间（过几天、明天、下周、这两天、准备买）；⑤ 已锁定我方，只在我方不同型号/套组间犹豫。立即跟进，确认购买时间、型号与优惠承接。
B 级① 对比竞品或其他品牌（华为、小米、品牌B、其他品牌、哪个好、区别）；② 有购买计划/复购（打算买、下个月买、以后买、再买一台、计划购买、考虑）；③ 客户提了实质需求，但客服还没回答客户就离开。主动跟进，询问购买时间与对比重点，尝试留联系方式。
C 级① 客户消息 ≥ 5 条，围绕参数/功能反复咨询；② 跨天/隔天再次咨询；③ 有大概需求但无明确购买信号。作为培育线索记录，后续结合再次咨询适度跟进。
关键区分：对比竞品/其他品牌属于 B；已锁定我方、只在我方不同型号/套组间犹豫属于 A。历史「√√ / √ 重点关注」已废弃，统一用 A/B/C 表达。

9.5 电销线索（单独标记）

出现电话号码，或命中「电话、手机号、联系方式、微信、加V、留个号、联系我」等关键词，即标记为电销线索：同时判为有效 + A 级，并出现在「电销跟进」页。号码识别支持平台脱敏格式（如 159*******5）与带分隔符格式，规则见第 7 章。

9.6 评分规则（售前，满分 100 倒扣）

维度怎么算扣分上限
响应速度从客户第一条消息到客服（或机器人）第一次回复的时长。≤20 秒 0 分；≤60 秒 2 分；≤180 秒 5 分；更久 10 分。10 分
售前必问三组信息在客户表述中出现了几组：会议室规模/人数、视频会议需求、使用场景。三组全中 0 分；中两组 5 分；中一组 10 分；一组没有 20 分。20 分
问题解决客户有实质问题，但客服完全没有回复。扣 20 分；其余情况不自动扣分，进入人工判断。20 分
引导留资是否拿到联系方式，或主动引导留资。已获得 0 分；主动询问但未获得 0 分；全程未尝试 5 分。5 分

合格线：计算分 ≥ 60 为合格，< 60 为不合格；命中可疑项或有效性待复核时，最终状态为「待复核」，需要人工确认。售后不评分，仅记录。

9.7 致命项（需人工确认）

类型典型表述（关键词示例）
辱骂客户傻、垃圾、滚、脑子有问题
诱导私下交易私下、加微信转账、微信转账、不要平台、线下付款
泄露敏感信息身份证号、银行卡号、密码、验证码
虚假承诺 / 价格承诺绝对最低价、保证最低、绝对不会涨价、百分之百、永久保价

命中的只是「致命候选」，会在详情页提示数量与原文，必须人工确认；确认后该项会话固定 59 分并判不合格。

9.9 AI 辅助判定

  • 对可疑会话逐条请求 AI，输出「合格 / 不合格 / 待复核」+ 理由 + 改进建议 + 引用原文（第 N 条）。
  • 结果以「智能：」前缀展示，只作参考，不改变规则算出的分数；相同内容命中缓存时不重复调用。
  • AI 不可用或返回异常时，会话仍保留规则结果，不影响正常质检。

10常见问题

Q1：双击 start.bat 没反应 / 窗口一闪而过？

先确认电脑已安装运行环境（由管理员统一部署）；仍打不开时，在项目文件夹内打开终端运行 start.bat 查看报错信息，把截图发给技术支持。

Q2：提示「该聊天记录已于 X 导入过」，是出错了吗？

不是，这是自动去重。同一份聊天记录只需导入一次；若数据有更新，请导出新的 .log 再导入。

Q3：客户明明留了电话，为什么没进电销跟进？

确认号码是否满足：以 1 开头、第二位 3–9、共 11 位、最后一位是数字；掩码格式（159*******5）可以识别，带空格或短横线也可以。号码被拆成多行、写在图片里、或位数不完整时无法识别。

Q4：我改了分数，为什么总览没变化？

改分后必须点「确认合格 / 改判不合格」其中一个按钮保存；保存成功后总览分数立即更新。只改数字不点按钮，弹窗关闭后修改不会保留。

Q5：待复核队列太多了，怎么快速处理？

优先看 A 级商机、电销线索和「客户未等到客服回复」的会话；分不清时先看判定原因与聊天记录，再按实际情况改判并写清理由。复核完的行会自动移出队列。

Q6：AI 批量质检很慢或失败？

批量质检是一会话一次接口调用，受网络与接口速度影响；失败不影响规则结果，可稍后重试。先在「智能设置」点「测试连接」确认配置可用。

Q7：界面是深色，看着累，怎么换成浅色？

点右上角月亮/太阳图标切换主题，默认就是浅色；选择会被记住。

Q8：导错了一批数据，能删吗？

可以，在「数据导入」页的历史批次中选中该批次，点「删除选中批次」；会同时删除该批次的会话、质检结果与 AI 缓存，不可撤销，并写入审计日志。

Q9：规则词不够用，想加关键词？

请技术同事修改 config 下的 rules.yaml / scoring.yaml 后，删除对应批次重新导入即可生效。建议先在测试数据上验证再用于正式数据。

Q10：数据存在哪里？安全吗？

所有数据保存在本机 data/qc.db（SQLite）中，AI 密钥保存在本地配置文件里，不上传云端；只有使用 AI 功能时，会话文本会发送到公司配置的 AI 接口。
