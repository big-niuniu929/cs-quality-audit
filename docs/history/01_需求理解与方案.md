# 品牌A 客服质检系统 4.0 — 需求理解与实施方案

> 基于《客服质检系统全景规范》、迁移交接主提示词、问卷答案、以及真实样本探查。
> 本文档是 4.0 版本的基线方案。

## 一、需求复述（对齐你 11 条回复）

1. **数据源**：在 API 自动读取之前，数据由你人工导入，每次导入**一对文件**——聊天记录 `.log`（正文）+ 会话记录 `.xlsx`（标签统计）。流程沿用旧系统，但不再是单个 `.log`。
2. **三家店铺**：之后分别导入各店铺的数据。会话记录里有型号、SKU（产品编号）、客服、顾客，但**无法识别店铺** → 导入时**手动标记店铺**，同店铺数据归流。支持跨店铺看某个品，也支持看单店客服情况。
3. **筛选**：必须支持按客服 / 产品 / 时间 / 售前售后 / 商机等级 / 有效性等维度筛选。
4. **整体化**：不再拆成多个 HTML，系统是一个整体；UI 按《液态水晶玻璃UI设计系统-规范.md》统一。
5. **客服账号去前缀（宽容模式）**：已知账号集合 + `brandb` 前缀双重识别客服，显示时去掉前缀；其他店铺新客服靠前缀自动识别，识别不了直接当客户填入、不报错。
6. **AI**：不是不能用，是要把接口从写死的 `/chat/completions` 改成兼容公司 `ai.公司内网.com` 的 Responses + Chat Completions 双协议。
7. UI 统一（同 4）。
8. **留资**：以 `scoring.yaml` 扣分制为准（最高扣 5 分，没尝试留资扣 5 分，获得联系方式/主动引导被拒不扣分）。
9. **内部闲聊**：标「无效 + 特殊原因」，不作为独立业务维度，需要 AI 介入识别。
10. **A/B/C 边界**：已固化为可执行规则（见 `02_商机判定规则ABC.md`）。
11. **评分维度**：话术匹配度、优惠触达本轮不计分，只跑 4 个计分维度（响应速度、售前必问、问题解决、留资）。
